## Core Concept 1 — CLAUDE.md
### CLAUDE.md とは
プロジェクトのルートに置くファイルで、Claude Code にリポジトリのコンテキストを伝えるためのもの。

### CLAUDE.md に書くべきこと
1. **プロジェクトの概要**
   - 何のコードか、誰が使うか

2. **開発規約**
   - コーディングスタイル、命名規則
   - 使ってよいライブラリ、使ってはいけないパターン

3. **ビルド・テスト手順**
   - どのコマンドを使うか
   - CI の前提条件

4. **重要な制約**
   - 触ってはいけないファイルや領域
   - 本番に影響するオペレーションの注意事項

5. **繰り返し聞かれることへの回答**
   - Claude が毎回聞きそうな前提条件を先に書く

### CLAUDE.md のアンチパターン
- 何も書かない（Claude がコンテキストを推測するしかない）
- 矛盾した情報を書く
- 古くなっても更新しない
- 全部入れようとして長くなりすぎる

### One-line mental model
CLAUDE.md = Claude に渡す「このプロジェクトのルールブック」

## Core Concept 2 — Rules, Skills, Plan Mode
### Rules
- Claude Code の動作ルールを定義する
- 例: 特定のファイルを読み取り専用にする、特定のコマンドを禁止する
- プロジェクト全体に適用されるガードレール

### Skills
- 繰り返し使う操作のテンプレート
- 例: テスト実行のフロー、PR 作成の手順
- チームで共有できる再利用可能なパターン

### Plan Mode
- Claude が実行前に計画を提示し、人間が確認してから進む
- 破壊的操作・複雑な変更・重要なファイルへの操作で使う
- 自動承認で進めてしまう前に「一度止める」仕組み

### 使い分けの判断
| 状況 | 使うべき機能 |
|---|---|
| プロジェクト規約を Claude に伝えたい | CLAUDE.md |
| 特定の操作を禁止したい | Rules |
| 繰り返し使うフローを定型化したい | Skills |
| 実行前に確認ステップを挟みたい | Plan mode |

## Core Concept 3 — When to Use Claude Code
Claude Code を使うべき場面と避けるべき場面を判断できることが大事。

### Use Claude Code when...
1. **繰り返しの実装タスク**
   - テスト生成、ドキュメント更新、定型リファクタリング

2. **コードの説明や理解**
   - 既存コードの解析、設計上の意図の確認

3. **定型的なレビュー**
   - フォーマット確認、命名規則チェック

4. **CI/CD への統合**
   - 自動テスト生成、品質ゲートの自動チェック

5. **新しいコンテキストのオンボーディング支援**
   - CLAUDE.md があれば新しい Claude セッションでも文脈を引き継げる

### Do NOT use Claude Code when...
1. **高リスク操作をレビューなしで自動化**
   - 本番データの変更、外部 API への書き込み

2. **規約や制約が CLAUDE.md に書かれていない**
   - Claude がプロジェクト固有のルールを知らない状態で動かす

3. **人間の判断が必要な設計決定**
   - アーキテクチャの選択、ビジネスロジックの解釈

4. **機密情報を含む操作**
   - 認証情報、個人情報の扱いが必要なタスク

5. **検証手段がない場合**
   - 結果を人間が確認できない or テストで検証できない操作

## Claude Code in CI/CD
CI/CD での Claude Code 活用は、試験シナリオ「Claude Code in CI/CD」に直結する。

### CI での活用例
- PR 作成時に自動でコードレビューコメント生成
- テストカバレッジの不足箇所を指摘
- セキュリティ上の懸念をフラグ

### CI での設計原則
- **fail-fast**: 問題を早期検知して後工程への影響を防ぐ
- **フィードバックの明確化**: Claude の出力がレビュー可能な形で残る
- **自動承認の範囲を絞る**: 変更の適用は人間の承認後にする

### アンチパターン
- CI で Claude Code が本番コードを直接書き換える
- エラーが出ても pipeline が続行する
- Claude の判断だけを根拠に merge を自動化する
